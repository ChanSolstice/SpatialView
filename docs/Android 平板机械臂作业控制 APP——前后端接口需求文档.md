# Android 平板机械臂作业控制 APP  
# 前后端接口需求文档

## 1. 文档目的

本文档用于定义 Android 平板 APP 与 ROS2 服务端之间的接口需求。

系统通信架构：

```text
Android APP
    ↓
ROSbridge
    ↓
ROS2 Humble 服务端
    ↓
机械臂 / 扫描 / 重建 / 规划 / 工艺模块
```

本文档明确：

- 前端需要哪些接口；
- 每个接口的业务目的；
- 前端需要哪些数据；
- 服务端需要返回哪些状态；
- 各接口之间的数据关联关系。

本文档暂不确定：

- ROS Topic 名称；
- ROS Service 名称；
- ROS Action 名称；
- ROS Message 类型；
- ROSbridge 地址及端口；
- 实际字段名称；
- 实际枚举值；
- 错误码；
- 超时时间；
- 发布频率。

以上具体内容由服务端开发人员确认并填写。

# 4. 公共数据关联

建议服务端建立以下数据关联关系：

```text
task_id
   │
   ├── model_id
   │
   ├── surface_ids
   │
   └── plan_id
          │
          ├── TCP Cartesian Path
          └── Joint Trajectory
```

其中：

`model_id`

用于唯一识别一次有效重建模型。

`plan_id`

用于唯一识别一次规划结果。

规划必须明确绑定对应：

`model_id`

防止新模型错误使用旧规划结果。

如服务端存在完整任务管理机制，可同时提供：

`task_id`

---

# 5. 模型与规划保存说明

服务端需要能够保存近期模型及规划数据，具体保存数量当前建议为：

**最近 5 次。**

该要求主要用于：

- 服务端数据管理；
- 故障排查；
- 模型与规划 ID 匹配；
- 防止当前任务数据混淆。

但 **Android APP 不提供历史模型浏览、选择或重新加载功能。**

因此：

- 不需要历史模型列表接口；
- 不需要历史规划列表接口；
- 不需要加载历史模型接口；
- 不需要加载历史规划接口。

APP 正常情况下只显示和使用：

**当前任务对应的有效模型及有效规划结果。**

# 6. 公共响应要求

控制类接口建议至少包含以下语义信息。

| 语义 | 是否需要 |
|---|---|
| 请求是否成功收到 | 是 |
| 请求是否被接受 | 是 |
| 请求唯一标识 | 建议 |
| 执行结果 | 是 |
| 错误码 | 是 |
| 错误描述 | 是 |
| 当前业务状态 | 建议 |
| 时间戳 | 建议 |

重要控制指令建议具备防重复执行机制。

例如：

用户点击一次“开始规划”，由于网络异常未及时收到响应，不应因为前端重发请求而产生两个规划任务。

# 43. 接口设计原则

本项目中：

**前端负责展示、选择和控制。**

**服务端负责算法、状态判断、数据生成及设备实际执行。**

前端不负责：

- 点云显示及处理；
- 三维重建；
- Surface 算法划分；
- 路径规划；
- 实际机械臂状态推导；
- 机械臂实时姿态镜像；
- 历史模型管理；
- 历史规划加载；
- 标定功能；
- 安全状态判断。

所有影响实际机械臂运行的重要状态均以：

**服务端反馈为准。**

Android APP 始终围绕：

**当前任务、当前模型、当前规划**

进行展示与控制。
