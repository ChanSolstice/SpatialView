本文把[架构设计](架构设计.md)第 9 节的里程碑 M0–M4 拆成 13 个可以逐个完成、逐个验收的阶段，用来安排开发顺序和跟踪进度。每个阶段写明做什么、依赖什么、做到什么程度算完成。功能和行为以[需求文档](需求文档.md)为准，接口以[服务端对接接口文档](服务端对接接口文档.md)为准，界面以[前端UI设计](前端UI设计.md)为准；本文只引用章节编号，写作"需求 x.y""接口 x.y""架构 x.y""UI x.y"。

读者：APP 团队；服务端团队看第 3 节。

**使用方法**

- `[ ]` 为未完成，`[x]` 为已完成。
- 一个阶段的任务和完成标准全部勾选后，才在第 1 节中勾选该阶段，并在行末注明完成日期和提交号，例如"（2026-10-20，abc1234）"。
- 里程碑除了包含的阶段全部完成，还要满足该行列出的条件，这些条件通常依赖服务端团队（第 3 节）。
- 阶段内的任务可以调整顺序。增删任务、调整阶段时修改本文，并在版本表中说明。
- 本文不安排时间，时间在确定人员后另行制定（架构 9）。

### 阶段 1：样例数据与文件校验（M0）

- [x] `tools/validate`：按接口 10.2 检查 GLB（单 primitive 的表面节点、`extras`、节点没有变换、没有做 Y-up 转换、规模），按接口 11.2 检查规划文件（时间轴、点数、关节名、`process_on`、与模型的 ID 对应）；命令行逐条输出结果
- [x] 开发用机械臂模型：官方 `aubo_i5H.urdf` 和网格（解开符号链接）放入 `app/public/robot/`，加一个示意工具连杆（沿法兰 Z 轴 0.15 米）；附来源和许可证说明（BSD）。服务端交付正式 URDF 后替换（第 3 节）
- [x] `tools/sample_data`：生成大样例（约 30 万三角面、约 500 个表面；两个数组各 10 万点）和单元测试用的小样例。工件放在 i5H 的工作范围内；关节轨迹按 i5H 运动学求出，工具末端沿 TCP 路径
- [x] 校验工具的测试：每条规则至少有一个通过和一个不通过的样例

完成标准

- [x] 全部样例通过校验。大样例 292,834 个三角面、483 个表面、98,459 点；两组 GLB 在 Khronos glTF Validator 中也没有任何问题
- [x] 故意做错的样例（做了 Y-up 转换、多个 primitive、时间不递增、关节名与 URDF 不一致等）都被校验工具指出
